.java file is the human readable file and it consists of the source code 

A compiler takes the .java file and converts it into .class file, which is called the byte code:    
            - this code will. not directly run on a system 
            - Java Virtual Machine (JVM) is required to run this 
            - this is what makes java platform independent 

An interpreter then converts this compiled .class code into machine code of 0 and 1, this is done line by line 

Platform Independence: the byte code (.class) can run on any os, but machines only understand 0 and 1, hence interpreter is used to convert .class to machine code 
----------------------------------------------------------------------------------------------------------------
JDK vs JRE vs JVM vs JIT:
    1) The Role of the JDK (Java Development Kit) — The Workshop
        - When you write your code, you use the JDK.
        - The JDK contains everything you need to build software, including the compiler (javac).
        - You run javac HelloWorld.java, and the JDK translates your human-readable text into HelloWorld.class (bytecode). Once compiled, you don't technically need the JDK anymore to run it—just the JRE.

    2) The Role of the JRE (Java Runtime Environment) — The Engine Room
        - To actually execute HelloWorld.class, you need the JRE.
        - The JRE provides the runtime environment. Crucially, it includes the JVM and the core Java library classes (like System.out, which Java uses to print to your console). Without the JRE, Java wouldn't know what System.out.println means.

    3) The Role of the JVM (Java Virtual Machine) — The interpreter
        - The JRE fires up the JVM.
        - The JVM loads your .class file and reads the bytecode.
        - It acts as an interpreter, converting bytecode into your computer's specific machine code (0s and 1s) line by line so your CPU can execute it.
    
    4) JIT: the part which provides direct machine code to methods that are reparted in source/.class code
